Section 02

System Architecture

The warehouse operates as a pipeline with three physical zones and one software layer orchestrating all of them.

Zone Function Constraint
ASRS Stores the full article inventory. Automated cranes retrieve crates on WMS command. Bounded retrieval throughput. 45–90 s per crate depending on storage location.
Waiting area Buffer zone between ASRS exit and PTL stations. Crates held until the right release moment. Decouples ASRS retrieval timing from station dispatch timing.
PTL stations (×24) Operator-guided sorting. Each station holds 10 racks and a backlog of up to 6 pending orders. Operator confirmation events must be received and processed in real time.

The WMS orchestrates all three zones continuously. It receives orders from SAP, assigns them to stations, triggers ASRS retrievals at the right moment, controls waiting area releases, drives PTL light signals, and tracks wave progress against truck deadlines — all from a single shared database that serves as the only integration point between the software layer and the physical equipment.

The database as integration boundary

This database-as-integration-boundary is an architectural choice, not a default. It means no software component has direct knowledge of another's internal state. The ASRS PLC reads retrieval commands from the database and writes completion events back to it. The PTL controller reads light instructions and writes operator confirmations. The WMS reads all of this and writes its decisions. Each layer is isolated; the shared state is the only contract between them.

This is what makes the IT/OT boundary tractable — and what makes the system testable and reconfigurable without touching every component at once.
